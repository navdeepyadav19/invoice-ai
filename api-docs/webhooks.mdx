Webhooks let your systems hear about invoice activity without polling. When something happens to an invoice, Invoice-AI sends a signed `POST` to every endpoint you've registered for that event.

Deliveries are queued by the database in the same transaction that records the invoice event, so every recorded event reaches every subscribed endpoint. That includes `invoice.viewed` and `invoice.downloaded`, which your customer triggers from the public invoice link and which never pass through the API.

## Register an endpoint

Register an endpoint with the API (scope `webhooks:manage`), or in the web app under **Settings → Webhooks**.

<CodeGroup>
```bash curl
curl https://invoice.horizonpay.co/api/v1/webhook-endpoints \
  -H "Authorization: Bearer $INVOICE_AI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/hooks/invoice-ai",
    "events": ["invoice.finalized", "invoice.paid", "invoice.voided"]
  }'
```


<ParamField body="url" type="string" required>
  Where to send events. It must be `https://`, and its hostname must resolve to a **public** address. Private, loopback, link-local, carrier-grade NAT and multicast ranges are rejected with `422`.
</ParamField>
<ParamField body="events" type="string[]">
  Which [events](#events) to receive. Leave it out, or send an empty array, to receive **every** event, including event types added later. An unknown event name returns `422`.
</ParamField>

<Warning>
  The signing `secret` is returned **only in this create response**. `GET /webhook-endpoints` never includes it. If you lose it, delete the endpoint and register it again.
</Warning>

To list your endpoints, call `GET /webhook-endpoints`. To remove one, call `DELETE /webhook-endpoints/{id}` with the endpoint's UUID. It returns `204`, and deleting an endpoint that's already gone returns `404`. You can't update an endpoint. Delete it and create a new one.

## Events

| Event | Sent when |
|---|---|
| `invoice.created` | A draft was created. |
| `invoice.updated` | A draft was edited, including lines added or removed. |
| `invoice.finalized` | An invoice was finalized: it got its number and is now `open`. |
| `invoice.emailed` | An invoice was emailed to a customer. |
| `invoice.email_failed` | Sending an invoice email failed because the email provider returned an error. Later bounces aren't tracked. |
| `invoice.viewed` | A customer opened the public invoice link. |
| `invoice.downloaded` | A customer downloaded the PDF. |
| `invoice.paid` | An invoice was marked paid. |
| `invoice.voided` | An invoice was voided. |

There's no `invoice.overdue` event, because overdue is [worked out when an invoice is read](/invoice-lifecycle#overdue) and never stored.

    </ResponseField>

<Tip>
  The payload is a notification, not the full record. For line items, minor-unit totals or the latest state, call `GET /invoices/{data.invoice_id}` after you verify the signature.
</Tip>

## Verifying signatures

Deliveries are signed with [Standard Webhooks](https://www.standardwebhooks.com/). Three headers come with each request:

| Header | Value |
|---|---|
| `webhook-id` | The delivery id, a UUID. It's the same on every retry of that delivery. |
| `webhook-timestamp` | When this attempt was signed, in Unix seconds. |
| `webhook-signature` | `v1,` followed by a base64 HMAC-SHA256 signature. It may hold several space-separated signatures. |

To verify a delivery:

1. Build the signed content: `{webhook-id}.{webhook-timestamp}.{raw request body}`.
2. Decode your secret: take the part after `whsec_` and **base64url**-decode it to get the key bytes.
3. Compute HMAC-SHA256 of the signed content with those bytes, then base64-encode it (standard alphabet, with padding).
4. Compare `v1,<your result>` with each space-separated value in `webhook-signature`, in **constant time**.
5. Reject the request if `webhook-timestamp` is more than **5 minutes** from your clock, in either direction.

<Warning>
  Verify against the **raw bytes** of the body, before any JSON parsing. A body that's parsed and re-serialized won't match the signature.
</Warning>

<CodeGroup>
```javascript Node.js (Express)
import crypto from "node:crypto";
import express from "express";

const SECRET = process.env.INVOICE_AI_WEBHOOK_SECRET; // whsec_…
const TOLERANCE_SECONDS = 5 * 60;

function verify(headers, rawBody) {
  const id = headers["webhook-id"];
  const timestamp = headers["webhook-timestamp"];
  const signatures = (headers["webhook-signature"] ?? "").split(" ").filter(Boolean);
  if (!id || !timestamp || signatures.length === 0) return false;

  const now = Math.floor(Date.now() / 1000);
  if (!Number.isFinite(Number(timestamp)) || Math.abs(now - Number(timestamp)) > TOLERANCE_SECONDS) {
    return false; // too old or too far in the future
  }

  const key = Buffer.from(SECRET.replace(/^whsec_/, ""), "base64url");
  const expected =
    "v1," + crypto.createHmac("sha256", key).update(`${id}.${timestamp}.${rawBody}`).digest("base64");

  return signatures.some((candidate) => {
    const a = Buffer.from(candidate);
    const b = Buffer.from(expected);
    return a.length === b.length && crypto.timingSafeEqual(a, b);
  });
}

const app = express();

app.post("/hooks/invoice-ai", express.raw({ type: "application/json" }), (req, res) => {
  const rawBody = req.body.toString("utf8");
  if (!verify(req.headers, rawBody)) return res.status(400).send("invalid signature");

  const event = JSON.parse(rawBody);
  // Deduplicate on req.headers["webhook-id"] before acting on the event.
  console.log(event.type, event.data.invoice_number);

  res.sendStatus(204); // any 2xx acknowledges the delivery
});

app.listen(3000);
```

```python Python (Flask)
import base64, hashlib, hmac, os, time
from flask import Flask, abort, request

SECRET = os.environ["INVOICE_AI_WEBHOOK_SECRET"]  # whsec_…
TOLERANCE_SECONDS = 5 * 60


def secret_bytes(secret: str) -> bytes:
    raw = secret.removeprefix("whsec_")
    return base64.urlsafe_b64decode(raw + "=" * (-len(raw) % 4))


def verify(headers, raw_body: bytes) -> bool:
    msg_id = headers.get("webhook-id")
    timestamp = headers.get("webhook-timestamp")
    signatures = headers.get("webhook-signature", "").split()
    if not msg_id or not timestamp or not signatures:
        return False

    try:
        if abs(time.time() - int(timestamp)) > TOLERANCE_SECONDS:
            return False
    except ValueError:
        return False

    signed = f"{msg_id}.{timestamp}.".encode() + raw_body
    digest = hmac.new(secret_bytes(SECRET), signed, hashlib.sha256).digest()
    expected = "v1," + base64.b64encode(digest).decode()

    return any(hmac.compare_digest(candidate, expected) for candidate in signatures)


app = Flask(__name__)


@app.post("/hooks/invoice-ai")
def invoice_ai_webhook():
    raw_body = request.get_data()  # raw bytes, before any JSON parsing
    if not verify(request.headers, raw_body):
        abort(400)

    event = request.get_json()
    # Deduplicate on request.headers["webhook-id"] before acting on the event.
    print(event["type"], event["data"]["invoice_number"])
    return "", 204
```
</CodeGroup>

<Note>
  **About Standard Webhooks libraries.** The official `standardwebhooks` packages expect the part of the secret after `whsec_` to be standard base64. Invoice-AI secrets are **base64url**, so they may contain `-` or `_`, and those libraries can then reject the secret or derive the wrong key. Until that's resolved, use the snippets above. They follow the same algorithm, with a base64url decode of the secret.
</Note>

## Responding and retries

- **Acknowledge with any `2xx` within 10 seconds.** Do the slow work after you respond, for example on a queue.
- **Anything else is a failure**: a `3xx` (redirects aren't followed), `4xx`, `5xx`, a timeout, a DNS failure or a URL that now resolves to a private address.
- **Delivery is at least once.** A delivery can arrive more than once, so deduplicate on `webhook-id`.
- **Order isn't guaranteed.** Use each event's `created_at`, or fetch the invoice, rather than relying on arrival order.

A failed delivery is retried on this backoff schedule, measured from the failed attempt:

| After attempt | Next attempt no sooner than |
|---|---|
| 1 | 1 minute |
| 2 | 5 minutes |
| 3 | 30 minutes |
| 4 | 2 hours |
| 5 | 8 hours |
| 6 | 24 hours |
| 7 | None. The delivery is marked **dead**. |

After **20 dead deliveries** with no successful delivery in between, the endpoint is disabled automatically. It stops receiving events and shows `"active": false` and a `disabled_at` timestamp. Any successful delivery resets the count to zero. To start receiving events again, register the URL again.

<Warning>
  **Delivery currently runs once a day.** Deliveries are sent by a scheduled worker that runs daily at 03:00 UTC, because of the hosting plan's cron limits. That has two effects:

  - A new event can take **up to about 24 hours** to arrive.
  - Each retry waits for the next daily run, so in practice retries are about a day apart, and a delivery can keep being retried for about a week before it's marked dead.

  Don't rely on webhooks for anything time-sensitive yet. For near-real-time needs, poll `GET /invoices` or `GET /invoices/{id}/events` in the meantime. The delivery cadence will get faster when the worker's schedule changes. The backoff schedule above stays the same.
</Warning>

## Security checklist

- Always verify the signature and timestamp before trusting a payload.
- Keep the `whsec_` secret on your server, never in client code.
- Use an HTTPS endpoint with a valid certificate on a public address. Other URLs are rejected when you register them and refused again at delivery time.
- Treat string fields such as the invoice number as untrusted input in whatever system you pass them to.
