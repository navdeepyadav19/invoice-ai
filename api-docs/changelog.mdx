<Update label="September 2026" description="v1">
  ## REST API v1

  The first public version of the Invoice-AI API, served at `https://invoice.horizonpay.co/api/v1`.

  **Resources**

  - **Business**: `GET /business` reads your business profile. It's read-only in v1.
  - **Customers**: create, list (with `query` and `include_deleted`), read, update and archive (`cus_…` ids).
  - **Products and prices**: a catalog of products (`prod_…`) and their one-time or recurring prices (`price_…`), with `unit_amount` in minor units. Recurring prices are data only in v1, and nothing bills automatically.
  - **Invoices**: create drafts, from catalog prices or ad-hoc lines, then update, delete, finalize, send, pay and void them. You can also download the PDF and read the event history (`in_…` ids).
  - **Invoice items**: add, list, read and remove single lines on a draft (`ii_…` ids).
  - **Webhook endpoints**: register, list and delete HTTPS endpoints.

  **Platform**

  - Bearer API keys (`inv_live_…`) with 11 scopes, managed only in Settings → API keys.
  - RFC 9457 `application/problem+json` errors with stable `code` values.
  - `Idempotency-Key` support. It's required on invoice creation and on every lifecycle action, with `Idempotent-Replayed` on replays.
  - Cursor pagination over `created_at` and `id`, with `limit` up to 100.
  - Per-key rate limits: 120 requests per minute and 10 sends per hour, reported through `RateLimit-*` headers.
  - Nine webhook event types, signed with Standard Webhooks HMAC-SHA256 and retried on a backoff schedule.
  - A public OpenAPI 3.1 document at `/api/v1/openapi.json`, and a Postman collection generated from it.

  **Hardening before SDKs**

  - `PATCH /invoices/{id}` is a true partial update: `customer` is optional and lines are kept unless `items` is sent.
  - Money uses each currency's own minor unit (¥5,000 is `5000`), in requests, responses and webhooks.
  - Webhook payloads carry the REST `Invoice` under `data.object`, with public ids and minor units. New signing secrets are standard base64.
  - `GET /webhook-endpoints` and `GET /invoices/{id}/events` are cursor-paginated.
  - `POST /invoices/{id}/send` returns `{ data: Invoice, emailed_to }`.
  - A malformed id is a `404`, an invalid `cursor` is a `422`, and a reused `Idempotency-Key` is the new `idempotency_mismatch` code.

  **Known limitations**

  - Webhook deliveries are currently sent once a day. See [Webhooks](/webhooks#responding-and-retries).
  - No business profile writes, credit notes, OAuth apps or API key management through the API.
  - There are no official SDKs or CLI yet. Use the OpenAPI document to generate a client.
</Update>
