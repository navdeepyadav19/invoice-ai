## Authenticate with an environment variable

In CI, don't run `invoice-ai login`. Set `INVOICE_AI_API_KEY` instead:

```bash
export INVOICE_AI_API_KEY=inv_live_...
invoice-ai whoami
```

The CLI picks a key in this order: the `--api-key` flag, then `INVOICE_AI_API_KEY`, then your saved profile. Give the CI key only the scopes the job needs.

## JSON output

Output is a table in a terminal and JSON when piped. Add `--json` to always get JSON, for example to use with `jq`:

```bash
invoice-ai invoices list --status overdue --all --json | jq -r '.data[].number'
```

A single object prints as the object itself. A list prints as `{ "data": [...], "next_cursor": ... }`. Messages and errors go to stderr, so stdout stays valid JSON.

## Never prompt

- Commands that ask for confirmation (`send`, `void`, `delete`, `archive`) need `--yes` when there's no terminal.
- `invoices create` starts a wizard in a terminal. Pass flags (`--customer`, `--price`) and `--no-interactive` to skip it.
- With `CI` set, the CLI never prompts. A command that would need a prompt fails with exit code `2`.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | API or runtime error, such as `invalid_state`, `not_found` or a network failure |
| `2` | Usage error: a bad flag or argument, or a prompt was needed without a terminal |
| `3` | Auth error: the key is missing or invalid (`401`), or it lacks a scope (`403`) |
| `4` | Rate limited (`429`), after the automatic retries |

## GitHub Actions example

This job emails every draft invoice each Monday:

```yaml .github/workflows/send-invoices.yml
name: Send draft invoices
on:
  schedule:
    - cron: "0 9 * * 1"
jobs:
  send:
    runs-on: ubuntu-latest
    env:
      INVOICE_AI_API_KEY: ${{ secrets.INVOICE_AI_API_KEY }}
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm install -g @horizonpay/invoice-ai-cli
      - run: |
          for id in $(invoice-ai invoices list --status draft --all --json | jq -r '.data[].id'); do
            invoice-ai invoices send "$id" --yes
          done
```

The key needs `invoices:read` and `invoices:send`. Sending is limited to 10 per hour per key, so a large batch ends with exit code `4`.
