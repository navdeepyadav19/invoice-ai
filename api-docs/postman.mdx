The repository has a Postman collection and environment, generated from the OpenAPI document. Run the collection in order and it takes an invoice through its whole lifecycle.

| File | Contents |
|---|---|
| [`invoice-ai.postman_collection.json`](https://github.com/navdeepyadav19/invoice-ai/blob/main/docs/platform/postman/invoice-ai.postman_collection.json) | Every request, in run order, with tests |
| [`invoice-ai.postman_environment.json`](https://github.com/navdeepyadav19/invoice-ai/blob/main/docs/platform/postman/invoice-ai.postman_environment.json) | `base_url` and `api_key` |

## Run it

<Steps>
  <Step title="Create a key">
    In [Settings → API keys](https://invoice.horizonpay.co/settings/api-keys), create a key with every scope and a short expiry.
  </Step>
  <Step title="Import both files">
    In Postman, choose **Import** and add the collection and the environment.
  </Step>
  <Step title="Set the key">
    Select the **Invoice-AI — production** environment and set `api_key`.
  </Step>
  <Step title="Run the collection">
    Open the **Collection Runner** and run the whole collection in order. Each request uses ids saved by the ones before it.
  </Step>
</Steps>

Or use [Newman](https://github.com/postmanlabs/newman):

```bash
newman run invoice-ai.postman_collection.json \
  -e invoice-ai.postman_environment.json \
  --env-var api_key=inv_live_...
```

<Warning>
  A run creates real, numbered invoices in your account and sends one real email to `delivered@resend.dev`. That email counts toward your [send limits](/rate-limits), and your account email must be verified.
</Warning>

To regenerate the collection after an API change, run `pnpm postman:gen` from the repository root.
